API

Inputs

Attach aerisKbd to a native kbd element. It adds presentation only: no roles, tab stops, keyboard listeners, models, outputs or methods. The same import includes span[aerisKbdKey] for a standard key and span[aerisKbdContent] for main-key styling. The content directive has no inputs.

@for (row of inputs; track row.name) { {{ row.name }}{{ row.type }}{{ row.defaultValue }}{{ row.description }} }

Standard key reference

All 24 built-in values for keys and aerisKbdKey are listed below. These are text glyphs, not SVG icons; their appearance follows the system font. Custom icons can come from any icon library.

@for (key of standardKeys; track key.value) { {{ key.value }} {{ key.label }} }

Interfaces

Design tokens

Background, text, border, typography and corner defaults follow the active Aeris theme.

@for (token of tokens; track token[0]) { {{ token[0] }}{{ token[1] }}{{ token[2] }} }

Accessibility

Native kbd describes user input; it is not a button. Keep shortcut registration and platform-specific labels in your application. Do not put interactive elements inside a key hint.

Built-in keys include visually hidden readable names; their visual symbols are hidden from assistive technology. For custom icons, include visually hidden text alongside the decorative icon. Keep visible key names consistent with shortcuts your application actually supports. Long labels wrap, text scales with the root font size, and no motion is introduced.

Tab / Shift+TabSkips the key hint. No tab stop is added. Any key or shortcutNo action is registered, captured or cancelled by Kbd. Application handlers remain responsible.
