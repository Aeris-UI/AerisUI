This example counts selected file keys in selectionKeys, including files hidden by filtering, collapsed branches, or other root pages. Folders are marked selectable: false and propagation is disabled, so the count does not include ancestor keys. Removing files acts on every selected key and restores focus to Columns. The delay simulates a request; retain nodes and selection until a real server confirms success, and announce failures without clearing selection.

TreeTable paginates root nodes, not individual descendants. Filtering and collapsing do not clear selected keys. In multiple row-selection mode, Ctrl or Meta + A selects only currently rendered selectable rows. Checkbox mode has no header select-all. With propagation enabled, selecting a checkbox affects the loaded selectable nodes in that rendered branch; under path filtering this can be only the matching descendants. A selected-key count can then include both folders and files, not just leaf records.

In lazy mode the server owns filtering, sorting, and root pagination. Selection persists by key, but checkbox propagation cannot select children that have not been loaded. totalRecords describes the remote root count, not selected files. Use stable keys and server-side authorization for bulk actions across unloaded data. Hiding a column here clears its filter and sort and preserves the remaining order; Name stays visible for tree navigation. Visibility is not an access-control boundary.

Custom editor state

The template receives the editor as its implicit value and as editor. Use the row or node metadata for application validation. Bind the control's accessible name and connect its value changes to the draft. Leaving the editor commits a valid draft. Switching cells commits the previous draft, or discards it if invalid, and opens the new cell immediately. Portaled controls must link their panels with aria-controls or aria-owns.

MemberTypeBehavior
valueWritableSignal<unknown>Draft value. Replace it with value.set(next); preserve number, boolean, Date, array, object, or null types.
originalValueunknownValue at edit start. Treat objects and dates as immutable; no deep cloning is performed.
validWritableSignal<boolean> Whether the draft may commit. Defaults to true. Update this from your form validation; invalid drafts stay open on blur and are discarded when switching cells.
ariaLabelstringDefault accessible name: Edit followed by the column header. Bind it to your editor control.
commit(event?)(event?: Event) => voidSaves a valid draft and finishes editing. Also runs automatically when focus or a pointer leaves the owned editor, or on an unconsumed Enter outside multiline fields.
cancel(event?)(event?: Event) => voidDiscards the draft and finishes editing. Escape also cancels unless a child control consumes it or has an open picker.

Interfaces

Editing permissions

The final permission is cellEditable(data, column, node) ?? column.editable ?? editable. True allows editing, false prevents it, and undefined inherits. The table setting is a default, not a master switch. The pure predicate can restrict whole rows or individual cells and receives the node as its third argument. Disabled nodes always remain non-editable, even when the predicate returns true. Each descendant keeps its own disabled state and editing permissions. Revoking permission cancels an active draft without saving. Read-only cells have no edit indicator or editing tab stop; double-click, Enter and F2 do not start an editor.

PropertyTypeDefaultDescription
AerisTreeTableColumn.editableboolean | undefinedundefinedOverrides the table default for a column. cellEditable has final priority unless the node is disabled.

Pinning

Both tables use stickyHeader, column pinned and the pinnedRows model. Column pinned accepts 'start' or 'end'; omit it for normal scrolling. Columns are displayed in start, normal and end groups without changing your configuration. Reordering stays within a pin group. Only loaded root keys are eligible for row pinning; child keys are ignored and expanded descendants stay with their root. Top wins duplicate keys. Normal filtering and root pagination apply first; within each pin group, current sorted order is preserved. Pinning never fetches unloaded nodes, duplicates ancestors or mutates source order. Persist pin state through your model. Oversized pinned regions revert to normal scrolling to leave at least 44px for normal content. Responsive stack mode disables sticking.

PropertyTypeDefaultDescription
AerisTreeTableColumn.pinned'start' | 'end' | undefinedundefinedPins the column to a logical edge, including its header and filter cell.

Accessibility

  • The native table uses treegrid semantics. Rows expose hierarchy level, sibling position, set size, expanded state, selected state, disabled state, and busy state.
  • Only one visible row participates in the tab order. Arrow keys move through the visible hierarchy without changing source order.
  • Sortable headers are native buttons and expose aria-sort. Resize separators are named and keyboard adjustable.
  • Checkbox mode uses native checkboxes with checked and mixed states. Single and multiple modes use row selection without checkbox visuals.
  • Scrollable viewports are keyboard focusable. Frozen columns retain native header and cell semantics, and stack mode keeps visible column labels.
  • Editing uses a named native text input. Enter commits, Escape cancels, blur commits, and focus returns to the cell after keyboard completion. Custom editors commit valid drafts when you leave them or press an unconsumed Enter outside multiline fields. Nested pickers keep their own keyboard behavior and remain part of the editor when portaled.
  • When showOverflowTooltip is enabled, truncated headers and cells use Aeris Tooltip to reveal their complete value.
  • Loading, empty, and no-results states use polite status regions. The integrated paginator supplies its own navigation semantics.
