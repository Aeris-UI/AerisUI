The count is the number of keys in selectedKeys, including selections on other pages or hidden by filtering. The header checkbox changes only the current filtered page; clearing selection clears every key. Bulk removal in this example applies to all selected keys, not just the visible rows, and returns focus to Columns. The delay simulates a request; a real application should retain data and selection until its server confirms success and announce failures without clearing selection.

The column chooser clears a hidden column's filter and sort, preserves visible-column order, and keeps Name available. Global search uses visible filterable columns. CSV export also follows the current columns order; hidden fields are excluded. Column visibility is presentation, not permission control: remove sensitive fields from data returned by your server.

With lazy, Table emits request state through lazyLoad but still filters, sorts, and paginates the supplied data locally. The header checkbox cannot select unloaded server records. For remote datasets, preserve stable keys in your controlled model and resolve selected records on the server; do not interpret the loaded rows or selection count as every matching record. The selectRows() helper accepts only keys present in the supplied data.

Custom editor state

The template receives the editor as its implicit value and as editor. Use the row or node metadata for application validation. Bind the control's accessible name and connect its value changes to the draft. Leaving the editor commits a valid draft. Switching cells commits the previous draft, or discards it if invalid, and opens the new cell immediately. Portaled controls must link their panels with aria-controls or aria-owns.

valueWritableSignal<unknown>Draft value. Replace it with value.set(next); preserve number, boolean, Date, array, object, or null types.
originalValueunknownValue at edit start. Treat objects and dates as immutable; no deep cloning is performed.
validWritableSignal<boolean> Whether the draft may commit. Defaults to true. Update this from your form validation; invalid drafts stay open on blur and are discarded when switching cells.

cancel(event?)(event?: Event) => voidDiscards the draft and finishes editing. Escape also cancels unless a child control consumes it or has an open picker.

Methods

Row reordering requires a unique, non-empty string or finite number in rowKeyField for every row. Sorting, non-empty global/column filters, paginator, lazy, loading, and active cell editing disable moves. Disabled rows stay fixed and cannot be crossed. Selection and expansion remain attached to their keys. Table state does not serialize row order: persist the data array in your application. TreeTable hierarchical reordering is not supported.

Interfaces and types

Editing permissions

The final permission is cellEditable(row, column) ?? column.editable ?? editable. True allows editing, false prevents it, and undefined inherits. The table setting is a default, not a master switch: an explicit column or cell true can enable editing when the default is false. The predicate can restrict whole rows or individual cells. Keep it pure. If permission is revoked during editing, the draft is cancelled without saving. Read-only cells still support normal selection and projected content.

PropertyTypeDefaultDescription
AerisTableColumn.editableboolean | undefinedundefinedOverrides the table default for a column. cellEditable has final priority.

Pinning

Both tables use stickyHeader, column pinned and the pinnedRows model. Column pinned accepts 'start' or 'end'; omit it for normal scrolling. Columns are displayed in start, normal and end groups without mutating your configuration. Reordering stays within a pin group. Pin keys refer to stable, unique row keys; top wins if a key appears on both sides. Normal filters and pagination apply first, then visible rows are grouped top, normal and bottom in their current sorted order. Pinning never fetches missing lazy data or duplicates records. Persist pin state through your own model; saveState, restoreState and reset do not own it. Oversized pinned regions revert to scrolling to leave at least 44px for normal content. Responsive stack mode disables sticking. Table expansion detail rows travel with their parent.

PropertyTypeDefaultDescription
AerisTableColumn.pinned'start' | 'end' | undefinedundefinedPins the column to a logical edge, including its header and filter cell.

Accessibility

Click or tap a row handle, then a destination handle to move without dragging. The pressed state and live instructions identify the picked row. Activate the same handle again or press Escape to cancel.

Row reorder handles are named native buttons with instructions. Use Alt + Arrow Up/Down to move a focused row; focus stays on that row and its new position is announced. Escape cancels pointer dragging. For non-drag pointer alternatives, provide buttons calling moveRow(), as in the Row reordering example.

  • Table uses native table, caption, thead, tbody, th, and td semantics.
  • Sortable headers are native buttons and synchronize aria-sort.
  • Selection uses native checkbox or radio controls, including a visible-row select-all checkbox for multiple mode.
  • When a context menu is bound, the native context menu gesture opens the configured Aeris ContextMenu for enabled body rows and exposes row metadata through table state and events.
  • Expandable rows use native buttons with synchronized aria-expanded.
  • Resizable columns expose named separator controls and keep the combined width of each adjusted column pair stable. Reorderable headers support pointer dragging and keyboard movement.
  • When showOverflowTooltip is enabled, truncated headers and cells use Aeris Tooltip to reveal their complete value.
  • Read-only cells have no edit indicator or editing tab stop. Double-click, Enter and F2 cannot start editing them.
  • Loading and empty states use status semantics and remain inside the table body.
  • Stack responsive mode preserves cell labels through generated row labels on narrow screens.
  • Use a meaningful caption for every data table, even when the visible description is brief.

Keyboard support

Editors commit valid drafts when you leave the cell or press an unconsumed Enter. Textareas keep Enter for new lines, and nested pickers handle their own keys. Escape cancels. The first available control receives focus on entry; keyboard completion returns focus to the cell without stealing focus from outside controls on blur.
